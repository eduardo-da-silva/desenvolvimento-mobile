Por que --host?

Expõe o servidor na rede local. Abra http://IP-do-PC:5173 no celular para testar o layout real.

Atenção

Service worker só funciona em HTTPS ou localhost. No IP da rede, o PWA não instala.

04 · service worker

Cache: escolha a estratégia certa

precache

App shell

JS, CSS, HTML e ícones. Baixados na instalação e servidos do cache. É o que faz o app abrir offline.

NetworkFirst

Dados da API

Tenta a rede, cai no cache se falhar. Bom para listas que mudam (/tasks).

StaleWhileRevalidate

Imagens, fontes

Responde do cache na hora e atualiza por baixo. Ótimo para recursos pouco críticos.

Outras: CacheFirst (assets imutáveis), NetworkOnly (login, pagamentos) e CacheOnly.

04 · service worker

Runtime caching no Workbox

networkTimeoutSeconds: 4: se a rede demorar mais de 4 s, usa o cache. É assim que o app "parece rápido" com sinal ruim.

04 · service worker

Atualização do app

Com autoUpdate

Deploy novo → o SW novo é baixado → assume o controle e a página recarrega, sem ação do usuário.

Alternativa

registerType: 'prompt' + componente UpdatePrompt (useRegisterSW) para perguntar antes. Indicado para formulários longos.

Testando de verdade

Por que build?

Em dev o SW é parcial. Teste sempre o build de produção.

Service Workers: status "activated"marque Offline e recarregue

06 · deploy

Publicar em HTTPS

GitHub Pages

Gratuito. Atenção ao base do Vite se o site ficar em /repositorio/.

Netlify / Vercel

Conectou o repositório, publica. Domínio .app grátis e HTTPS automático.

Servidor próprio

Nginx + Let's Encrypt. Fallback de rota para index.html.

Fabroku: plataforma que usamos nos projetos do IFC para publicar as aplicações.

Pegadinhas que quebram o PWA

  • Rotas do Vue Router sem fallback → 404 ao recarregar
  • Domínio de teste que muda a cada deploy → o APK aponta para um domínio fixo
  • Servir manifest.webmanifest e sw.js com cache longo → atualização não chega

Para a loja você precisa de uma URL estável. Ela será o conteúdo do aplicativo.

APK, AAB e lojas

Empacotando o PWA para o Android

07 · empacotar

Que tipo de artefato?

caminho desta aula

TWA: Trusted Web Activity

  • O Chrome abre seu site em tela cheia, sem barra
  • É o mesmo PWA: deploy web atualiza o app
  • APK minúsculo (~1–2 MB)
  • Ferramentas: PWABuilder (recomendado) ou Bubblewrap (opcional)
alternativa

Capacitor (WebView)

  • Embute o build dist/ dentro do APK
  • Plugins nativos: câmera, push, arquivos
  • Exige Android Studio e atualiza só pela loja
ArtefatoPara
.apkInstalar direto no celular (testes, distribuição por link)
.aab (App Bundle)Obrigatório para novos apps na Google Play
07 · empacotar

Caminho recomendado: PWABuilder

recomendado TWA (Trusted Web Activity): um app Android mínimo que abre o seu site no Chrome em tela cheia, sem barra de endereço. Não há código web dentro do APK; ele só aponta para a URL publicada.

Acesse pwabuilder.com e informe a URL publicada
Revise o relatório (manifesto, SW, segurança)
Package for stores → Android
Preencha Package ID, nome, versão e Signing key: New
Baixe o .zip

O zip contém

  • app-release-signed.apk para testar
  • app-release-bundle.aab para a Play Store
  • signing.keystore + signing-key-info.txt
  • assetlinks.json pronto

Guarde o keystore!

Sem a chave de assinatura (ou sem a de upload cadastrada), você não consegue publicar atualizações. Faça backup fora do repositório.

07 · empacotar

Digital Asset Links: tirando a barra de URL

sempre necessário

O que é

Prova de que o site autoriza este app a abrir em modo TWA. Sem ela, aparece a barra de URL. Vale para PWABuilder e Bubblewrap (não para Capacitor). O PWABuilder entrega o arquivo pronto: salve em public/.well-known/.

Erro nº 1

Com Play App Signing, a Google reassina o app. Use o SHA-256 do Play Console → Integridade do app, além do da sua chave.

Deve responder em https://seudominio/.well-known/assetlinks.json com application/json.

07 · alternativa

Alternativa: Capacitor

atenção Este slide não é um passo a passo completo: faltam configurações (ícones, splash, permissões, assinatura etc.). Requer mais estudo; veja capacitorjs.com/docs.

Use quando

Precisa de recursos nativos que o navegador não dá (Bluetooth, contatos, push nativo) ou de funcionar 100% embutido.

Custo

Mais peso, Android Studio na máquina e cada mudança passa por nova versão na loja.

07 · loja

Google Play: o que preparar

Conta e app

  • obrigatório Conta de desenvolvedor (taxa única)
  • obrigatório Criar app e enviar o .aab
  • recomendado Faixa de teste interno primeiro

Ficha da loja obrigatório

  • Ícone 512×512
  • Imagem de destaque 1024×500
  • 2+ capturas de tela (celular)
  • Descrição curta e completa

Conformidade obrigatório

  • Política de privacidade em URL pública
  • Declaração de segurança dos dados
  • Classificação etária

Onde aprender: Central de Ajuda do Play Console (support.google.com/googleplay/android-developer) e Políticas do Programa para Desenvolvedores (play.google.com/about/developer-content-policy).

Contas pessoais novas

  • Exigem teste fechado com testadores por ~14 dias antes de produção
  • O targetSdk mínimo muda todo ano

Confira os valores atuais no Play Console.

07 · loja

E o iOS?

grátis

Adicionar à Tela de Início

No Safari: Compartilhar → Adicionar à Tela de Início. O PWA funciona com ícone e tela cheia, usando as tags apple-touch-icon do slide 13.

pago

App Store

Exige conta Apple Developer (anual), Mac com Xcode e um app com valor além de um "site embrulhado" (diretriz 4.2). PWABuilder gera o projeto Xcode, mas a aprovação não é garantida.

Na prática: Android via TWA na Play Store; iOS via instalação pelo Safari.
